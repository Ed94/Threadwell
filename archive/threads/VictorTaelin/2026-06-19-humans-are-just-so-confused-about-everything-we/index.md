what I wrote isn't just true, it is how humanity operates

if we weren't so eager to name concepts in a way that appeals to our evolved meat brain intuitions, we could probably compress and unify our whole body of mathematical knowledge into a tiny fraction of its current length

what sparkled this specific tweet was a conversation about SupGen, where someone had an a-ha moment when I told them that synthesizing a proof to a formal statement is the same procedure as finding the solution to a set of equations.

researchers arbitrarily decided to give many different names to that:
- inductive program synthesis
- symbolic regression
- automated theorem proving
- constraint satisfaction
- type inhabitation
- higher order unification

all these are literally the same thing, per curry-howard's isomorphism.

and beyond just using different names, we also study these things as completely separate fields. for example, if you search the literature, you'll find most papers on program synthesis implement a solution that crafts programs given test equations, but not proofs. and papers on ATP implement a solution to finding proofs given theorems, but not programs. and they use different jargon, find the same problems, gravitate the same solution in full separation.

EVEN THOUGH THEY ARE WORKING IN THE SAME PROBLEM

this goes beyond programs/proofs, it happens everywhere. another example is how linearity is the obvious solution to implementing functional runtime with O(1) mutable buffers, and free of garbage collection, and massively parallel, and a thousand of other things. but we work on each of these "desired features" as separate problems even though they're all symptoms of the same underlying disease: human intuition biased towards thinking that sharing variables is "free"

it is just how we work, and it is depressing
