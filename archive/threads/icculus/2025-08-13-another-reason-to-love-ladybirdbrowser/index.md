In engineering, there are several ways to solve the same problem.  So people will always redo the same thing, just a little differently, because they can.

It is possible to design good APIs that almost never change (like the C language) and solve a lot of problems “once for all.”  However, many engineers (or, if this term pleases you more, software developers) and consumers overall share the sentiment that “change is progress.”  So we have these problems where people keep making things more complex, instead of more stable, because it feels like “progress.”  The only way I see to fix it is to lead by example.
